# Native task editor controls and assignment progress

Task details now edits the shared web reminderMinutes (off/null, or 1–10080 minutes before scheduled start), scheduleLocked and schedulingPreference (none/morning/afternoon/evening). Existing native local reminders consume the same fields. Saving a new reminder offers notification permission from that user action and explains disabled permissions. Scheduled date/start/end controls respect a saved lock; explicit unlocking allows a subsequent scheduling edit. A preferred time is planning guidance and never moves a task by itself.

Only fields changed from the editor baseline enter the task patch. Field-level expected values reject conflicting newer changes while unrelated task/recurrence/assignment metadata remains in the raw document. Transactions recheck the target's active board/section/task, unique identity, location and current schedule lock. A no-op false lock cannot bypass a lock added remotely; a real unlock is represented in the same guarded merge. The task draft captures its timezone/calendar so a live profile change cannot reinterpret its dates or times on save.

The assignment card uses the web assignment-progress, assignment-order and remaining-work read models. It shows saved assignmentId relationships, completed/total sessions, remaining estimates, deadline/late-session status and sequential readiness. Parent/session links recheck active unique destinations and open another task sheet; returning retains the original draft. Native parentTaskID subtasks remain a separate feature. Viewing progress never changes order, parent completion, focus ledgers, estimates or the schedule. Advanced assignment rescheduling remains on the web.

Verification: Node tests execute the real vendored summary models (including archived/duplicate identities, waiting/ready/review states, remaining work and no input writes). Swift tests exercise metadata patches, bounds/conflicts, remote lock/archive/location guards and the native assignment bridge. CI runs the full existing core suite in three timezones, builds the iOS app/widget and verifies the bundled read model. Manual sheet/picker/notification interaction remains a simulator/device check.
